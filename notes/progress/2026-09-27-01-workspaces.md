# V0.2 first slice: team-owned workspace configuration

Recorded 2026-09-27 (Asia/Kolkata). [Current progress](README.md)

## Purpose

Continue from `9f586f7` with the first bounded catalog increment: create, list, read, edit, and reload team-owned workspace configuration. Preserve identity behavior and the supported React/Vite toolchain. V0.2 also includes agents and flows; this step does not complete that milestone or introduce execution.

## Implementation

The work followed shared contracts, a new migration, backend services/routes, then frontend forms. Workspace configuration includes repository URL, source ref, default branch, sandbox image, working directory, and all four action strings. Every successful edit stores a new snapshot with a revision check. Team membership and write role are checked in the server transaction. Audit events omit configuration contents.

Relevant files:

- `packages/contracts/src/workspaces.ts` and public exports: request/response contracts and types.
- `packages/db/migrations/002_workspaces.sql`, migration registry, and `scripts/database.mjs`: current records, immutable versions, explicit runtime privileges.
- `apps/api/src/workspaces.ts`, `workspace-routes.ts`, `identity.ts`, and `app.ts`: use cases, shared authorization, revision conflicts, mutation guards.
- `apps/web/src/features/workspaces/` and shell/router integration: team catalog, complete forms, draft retention, read-only behavior, navigation protection.
- Workspace unit/integration/DOM checks plus identity migration/grant regression updates.
- [Learning guide](../learning/07-workspaces.md), [findings](../findings/workspaces.md), architecture/roadmap, and current indexes.

## Trade-offs and next step

The API keeps SQL in a focused service with an injected pool instead of adding a generic persistence layer. Generic resource/version tables support subsequent catalog types, but the database currently permits only workspaces. A data router enables dirty-form navigation protection while preserving the existing application/session structure. No dependency or framework migration was needed.

Next: define and implement the bounded agent catalog increment, then ordered flows with authorized references to immutable workspace/agent versions. Keep history/restore UI, secret references, runners, and actual execution outside this step.
